## Confirmed issues and reproduction

### P1 — Native phone OTP unavailable (open configuration blocker)

1. Open phone sign-in in the installed development build.
2. Attempt to proceed with the phone flow.
3. Observe the message that phone OTP is not configured and email login is available for existing accounts.

Native Firebase configuration is missing and native providers are omitted during development preparation. Configure the correct Firebase Android application and native provider files, then exercise valid OTP, incorrect/expired OTP, resend, and each role choice. Do not replace verification with a local bypass. Role selection implementation exists but its real-device successful registration path is unverified.

### P1 — Account login does not establish service access (open configuration blocker)

1. Open the signed-in customer account.
2. Open Orders: combined journeys reports the service session unavailable.
3. Open Help & support: support history requires a connected service session.
4. Open the persisted cart and select Review delivery & checkout.
5. Observe booking-services error and disabled Continue to secure payment.

The account API is healthy but reports `identityBridgeEnabled: false`. Configure and validate the trusted Firebase identity bridge and appropriate verified account identity. Retest protected operations and expired-session recovery. Signing in repeatedly cannot by itself enable a disabled server bridge. Checkout's email-verification suggestion is incomplete for this configuration failure; improve recovery copy using a typed service-unavailable reason.

### P1 — Android system bars overlap booking/address actions (fixed, partial device acceptance)

1. In the earlier APK, open Parcel and scroll to Continue.
2. Observe the action overlapping Android navigation controls; a tap could send the device Home.
3. Open Add another location and observe the heading near the status bar.

Changed viewport handling in `index.html` from `cover` to `contain` so Capacitor SystemBars supplies native insets. Rebuilt and reinstalled. Parcel/Vehicle Transport actions and address heading/footer now remain outside native system bars. Saved clean address evidence in `device-2026-10-14/address-safe-area.png`. Full keyboard and gesture-navigation matrix remains unverified.

### P2 — Cached cart lacks recognizable partner identity (open)

1. Open the persisted food cart while live restaurant listings are empty.
2. Continue to checkout review without submitting payment.
3. Observe generic Selected partner label despite visible cached items.

Persist partner display identity with the cart and explicitly show an unavailable catalog verification state. Continue requiring server verification before payment. Quantity 15 at ₹149 displayed a consistent ₹2,235 subtotal; quantities were not altered.

### P2 — Transient account reconnect screen interrupts workflow (needs isolated reproduction)

During Parcel checking, the global account-services-unavailable screen appeared. Later API health succeeded and Home was reachable. Capture request failure and profile polling timings, retain the draft booking form during recovery, and test offline/reconnect behavior. Root cause and repeatability were not established; this is an observation, not a confirmed crash.

### Catalog availability blocks shopping acceptance

Food and Grocery displayed honest empty states. Publish approved test restaurants/stores and products in a staging environment before testing details, filtering accuracy, stock, unavailable products, mixed-partner carts and successful checkout. Empty data alone is not evidence of a rendering defect.
