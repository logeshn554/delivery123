# Partner location acceptance

Android implementation: user-started location foreground service, visible persistent notification with Stop sharing, precise location/notification permissions, native authenticated callable uploads every 15 seconds, no persisted coordinate queue or boot restart. iOS source now registers a native Capacitor location plugin, requests Always authorization after foreground permission, enables the iOS background location mode and visible location indicator, and uploads through Firebase Functions. Both native clients reject stale positions (over 30 seconds) and accuracy worse than 100 metres; repeated upload failures stop tracking. Server checks current role, verified status, online state and explicit consent for every report. Consent withdrawal removes the current position and active tracking document and takes the partner offline.

Native identity is minted only for a verified online consenting partner and retains the linked Neon session claim. The service uses Firebase native Auth/App Check; signed registration and App Check initialization must be accepted on a real device before launch. The current position is retained server-side while the partner stays online; no route history is collected by these services. No availability or tracking accuracy is inferred when the reported location becomes stale.

The app must be visible when starting/resuming a service. This follows [Android foreground-service start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start). Uploads use the [Firebase callable client](https://firebase.google.com/docs/functions/callable), which carries native authentication and available App Check tokens.

Pending acceptance: signed Android devices on supported versions, precise/approximate permission, denied notifications, GPS off, screen locked, battery saver, app swiped away, process killed, network changes, session revocation, suspension, consent withdrawal, service restart and no stale replay; plus iOS signed build, staged When In Use/Always prompts, background upload, visible indicator, authorization revocation, app termination and no stale replay. Verify the native Firebase project matches the web project. No native build or device acceptance has been performed; the current Windows host has no Xcode toolchain.

Web continues to use foreground browser location and clearly states the app must stay open. Do not accept release Gate D/E based on source checks alone.
