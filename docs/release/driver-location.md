# Partner location acceptance

Android implementation: user-started location foreground service, visible persistent notification with Stop sharing, precise location/notification permissions, native authenticated callable uploads every 15 seconds, no persisted coordinate queue or boot restart. Recent positions only (30 seconds old maximum, accuracy at most 100 metres) are uploaded. Repeated connection failures stop the service; authorization failures stop immediately. Server checks current role, verified status, online state, explicit consent and linked session validity for every report. Consent withdrawal removes the current position and active tracking document and takes the partner offline.

Native identity is minted only for a verified online consenting partner and retains the linked Neon session claim. The service uses Firebase native Auth/App Check; signed registration and App Check initialization must be accepted on a real device before launch. The current position is retained server-side while the partner stays online; no route history is collected by this service. No availability or tracking accuracy is inferred when the reported location becomes stale.

The app must be visible when starting/resuming a service. This follows [Android foreground-service start restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start). Uploads use the [Firebase callable client](https://firebase.google.com/docs/functions/callable), which carries native authentication and available App Check tokens.

Pending acceptance: signed devices on supported Android versions, precise/approximate permission, denied notifications, GPS off, screen locked, battery saver, app swiped away, process killed, network changes, session revocation, suspension, consent withdrawal, service restart and no stale replay. Verify the native Firebase project matches the web project. No device acceptance has been performed.

Web and iOS still use foreground browser location and clearly state the app must stay open. iOS native background implementation and signed-device acceptance remain unfinished. Do not accept release Gate D/E based on Android source compilation alone.
