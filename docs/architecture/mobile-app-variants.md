# AllGo mobile app variants

The customer, merchant, and delivery partner apps use one versioned React and Capacitor source tree, with separate Android application IDs and URL schemes. `scripts/app-audiences.json` is the identity registry consumed by the web build, Android manifest, and build wrapper. `npm run android:merchant` and `npm run android:driver` build debug APKs into `.cache/apps/<audience>/`; `npm run build:merchant` and `npm run build:driver` produce partner web bundles. The ordinary `npm run build` remains the customer bundle. Build commands run sequentially because they share the generated web/native asset directories. Android selects one product flavor from the bundle metadata and merges its manifest with the common main and debug/release sources.

Each audience selects a distinct workspace after authentication. Customer accounts may apply for a partner account; this client does not grant partner roles. Merchant work requires an assigned restaurant or grocery identity. Partner accounts in the wrong app receive no partner feed. Server authorization remains authoritative.

Only the driver Android variant registers the native `DriverLocation` plugin and declares the foreground location service. Customer and merchant variants omit the service declaration. The service requires an authenticated driver session, fresh location permission, and an explicit in-app start. Each variant has an isolated deep-link scheme and Android application ID so debug builds can be installed side by side.

The current Android wrapper intentionally produces debug artifacts. Release builds still require the existing staging/production preflight, matching Firebase registration, signing credentials, operational readiness, and provider verification. Separate production Firebase registrations, iOS bundle registrations/archives, and authenticated runtime acceptance for each audience remain release gates. The merchant and driver source folders alongside this repository are not modified by these builds.
